FED Balance Sheet — 실제 공식 데이터 연결

[안내] 아래 내용은 기존 v1 로컬 실행 안내를 보존한 참고 자료입니다.
회사 v3 운영은 한국시간 매일 오전 7:15에 6개 원천의 사용 이력 전체를
다시 수집합니다. 화면 데이터가 바뀔 때만 Altibase JSON 버전을 교체합니다.
현재 v3의 화면과 회사 운영 세부 사항은 docs/README.md 및
docs/v3-implementation-handoff.md를 따르세요.

1. 화면 실행
   FedBalanceSheet_v1.html: 저장된 최신 공식 수집값을 인터넷 없이 표시합니다.
   StartDashboard.cmd: 로컬 서버를 시작하고 브라우저를 엽니다.
   서버 주소: http://127.0.0.1:8765/FedBalanceSheet_v1.html
   서버 모드의 “새로고침”은 공식 데이터 재수집 → 검증 → 화면 반영을 수행합니다.
   파일 모드의 “저장 데이터 다시 읽기”는 로컬 스냅샷을 다시 읽으며 원천에 접속하지 않습니다.
   파일 모드에서 최신 수집하려면 RefreshData.cmd를 실행한 뒤 화면을 다시 읽으세요.
   다른 PC로 복사할 때 HTML, assets, scripts, data/normalized를 함께 복사하세요.
   수집 및 로컬 서버는 Python 3 표준 라이브러리만 사용합니다. 이 PC의 Codex 제공 Python을
   우선 사용하며, 다른 PC에서는 PATH의 python을 사용합니다. 별도 API 키가 필요하지 않습니다.

2. 공식 원천
   H.4.1 전체 SDMX/XML:
   https://www.federalreserve.gov/releases/h41/data/FRB_h41_xml.zip
   뉴욕 연은 거래 결과:
   https://markets.newyorkfed.org/api/rp/results/search.json
   API 명세: https://markets.newyorkfed.org/static/docs/markets-api.html
   ON RRP는 operationType=Reverse Repo, term=Overnight, auctionStatus=Results인
   서로 다른 operationId만 합산합니다. API 필터와 별개로 응답의 실제 필드도 검증합니다.
   totalAmtAccepted의 USD를 1,000,000으로 나누어 USD millions로 변환합니다.
   주말·휴일을 사이에 둔 Overnight는 달력상 여러 날일 수 있으므로 termCalenderDays=1로 제한하지 않습니다.
   H.4.1 주간 평균 및 변화율 계열을 제외하고 정확한 Wednesday level 계열 ID만 읽습니다.
   FRED 대체값, 샘플값, 보간값을 사용하지 않습니다.

초기 적재 기준일
   H.4.1 주요 수요일 잔액의 원천 XML 최초 일자: 2002-12-18.
   뉴욕 연은 ON RRP 일별 조회 시작일: 2013-09-23.
   이 화면의 두 원천을 같은 수요일로 결합한 최초 관측일: 2013-09-25.
   따라서 통합 지표의 초기 적재는 2013-09-25부터 수행합니다.
   수집 코드는 ON RRP를 2013-09-23부터 연도별 조회하고, 수요일 행만 생성합니다.
   2002-12-18부터의 H.4.1 단독 이력은 현재 통합 화면에 별도로 적재하지 않습니다.
   기준일 변경 시 scripts/ingest.py의 START와 FIRST_JOINED_WEDNESDAY를 확인하세요.

3. 최초 실제 수집 결과
   관측일 2026-10-21 / 발표일 2026-10-22.
   수집 범위 2013-09-25 ~ 2026-10-21, 683개 연속 수요일 행.
   총자산 6,753,604 / TGA 945,153 / ON RRP 237 / 순유동성 5,808,214 (USD millions).
   은행 지급준비금 2,969,522 (USD millions).
   동일 수요일 ON RRP가 없는 11개 날짜는 null로 보존하며 순유동성도 N/A입니다.
   이 날짜를 선으로 연결하거나 이전 영업일 값 또는 0으로 채우지 않습니다.
   이후 재수집하면 최신 공식 발표일과 관측일로 자동 변경됩니다.
   실제 최신 정보는 화면의 관측일·발표일·수집 시각을 확인하세요.

4. 계산 및 해석
   순유동성 = 총자산 - TGA - ON RRP. 지급준비금과 다른 제품 정의 대용지표입니다.
   같은 시작·종료 수요일로 1/4/13/52주 변화 및 자산 내부 기여도를 계산합니다.
   ON RRP와 H.4.1 전체 역레포를 서로 대체하거나 중복 차감하지 않습니다.
   과거에는 H.4.1 Others에 기간물 등이 포함되어 ON RRP와 다를 수 있습니다.
   대차대조표 요약은 Table 5의 연준권 순액을 사용합니다. Table 1의 유통 통화와 구분합니다.
   기타 자산은 금·SDR 증서, 주화, 추심 중 항목, 은행 건물, 외화표시 자산,
   공표 기타 자산의 합계입니다. 차액을 임의 잔차로 끼워 넣지 않습니다.
   과거 대출시설 등 현재 분해표에 없는 항목은 자산 대사 차액으로 드러납니다.
   최신 자산·부채·국채 상세 대사 허용오차는 공표 반올림을 고려해 5백만 달러입니다.
   최신 허용오차 초과, 중복 날짜·거래 충돌, 필수 계열 변경, 핵심 결측 시 새 스냅샷을 배포하지 않습니다.
   자금시장 금리 스프레드와 상설 레포 이용액은 아직 미연결이며 화면에 명시됩니다.
   모든 지원되지 않은 값은 N/A로 유지합니다.

5. 파일 구성
   assets/actual-data.js: file://에서도 작동하는 검증된 실제 데이터 번들.
   assets/data.js: 파생 계산, 결측 처리, 실제 스냅샷 검증과 데이터 접근 계층.
   scripts/ingest.py: 재현 가능한 공식 원천 수집·정규화·검증.
   scripts/serve.py: 127.0.0.1에만 바인딩하는 로컬 서버.
   data/normalized/latest.json: 화면과 API가 사용하는 전체 스냅샷·출처·계열 매핑.
   data/normalized/h41-YYYY-MM-DD.json: 발표일별 스냅샷.
   data/raw/수집시각/: 변경하지 않은 원본 ZIP·JSON과 URL·SHA256 manifest.
   data/quality-report.json: 결측 날짜, 계열별 누락, 대사·교차검증 결과.
   화면 하단 “출처·데이터 검증”에서 정확한 입력값과 원천 계열 ID를 확인할 수 있습니다.

6. 갱신 및 오류
   자동 주기 작업은 추가하지 않았습니다. 재수집은 실행 파일 또는 서버 새로고침으로 요청합니다.
   서버에서 동시 재수집을 막고, 완료 후 60초 내 반복 요청은 기존 결과를 재사용합니다.
   네트워크 실패 시 기존 정상 스냅샷을 유지하고 오류를 표시합니다.
   원본 수집은 최대 3회 재시도합니다. 현재 스냅샷은 검증이 끝난 뒤 원자적으로 교체합니다.
   관측일이 현재 시점에서 8일 넘게 오래되면 오래된 데이터 배너가 표시됩니다.
   수집 시각은 실제 수집 시각이며 단순 화면 새로고침으로 바꾸지 않습니다.
   개발 상태 미리보기는 HTML URL에 ?preview=1을 붙인 경우에만 표시됩니다.
   원본 압축 파일과 서버 로그는 Git 제외 대상으로 설정되어 있습니다.

7. 공통 UI 규칙
   Vue 3.2.41 고정, 지정 CheckExpert layout.css 색상 변수와 Noto Sans KR 폰트를 사용합니다.
   한국어/영어, 다크/화이트 설정은 유지됩니다.
   assets/i18n.js가 언어 공통 사전이며 language-table.csv는 참조 테이블입니다.
   사전 변경 후 node scripts/export-translations.cjs를 실행합니다.
   CSV 다운로드에는 실제 데이터 상태·원 단위·수집 시각·원천 링크·거래 ID가 포함됩니다.

8. 검증 명령
   npm test
   npm run check
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-python.ps1 -Mode test
   npm run test:browser  (Playwright 설치 또는 NODE_PATH 필요)
   Python 검사는 원본 XML·JSON 재정규화 결과를 전체 스냅샷과 대조합니다.
   JavaScript 검사는 수요일 결합, 4개 기간 변화, 결측·0·부호·백분위·오래된 데이터 처리를 확인합니다.
   브라우저 검사는 실제 수치, 출처, 결측 기간, 파일 갱신, 한영·테마 및 3가지 화면 크기를 확인합니다.
